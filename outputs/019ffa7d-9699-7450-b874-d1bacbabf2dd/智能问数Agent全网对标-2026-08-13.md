# 智能问数 Agent 全网对标：2026-08-13

> 范围：当前 /Users/tonyorz/Data-Agent 代码实况 + 截至 2026-08-13 的官方产品文档、官方 GitHub 与论文。商业方案的内部 planner 通常闭源；表内明确区分源码、官方契约与论文/营销主张。

## 一句话结论

当前 Data-Agent 已不是图里 08-10 的版本：它的强项是**一个主 Agent + 可治理 Ontology + deterministic plan + Defect 同 revision 下钻 + semantic claim 发布前证据校验 + OIDC 入口 + 运行审计**。它的下一步不是增加第二主 Agent，而是先消除当前分支回归与信任边界缺口、把 22 个模型可见工具收敛、建立真实执行 scorecard，再补关系路径和可视化。

图中旧建议需要两处关键改写：

1. **WrenAI** 在 2026-05 已转为 open context/semantic compiler；它与当前 Ontology 的重叠比旧版更大，适合选择性借编译/lineage，不适合默认深集成成第二语义核。
2. **Vanna** 已于 2026-03-29 归档，只适合借 identity-aware tool registry 与 streaming UI 形状，不应成为新生产依赖。活跃的互补参考应优先看 **DataHub Analytics Agent**。

## 对 Data-Agent 的优先建议与验收门

### P0 · 修复当前 testcase bridge 安全与回归

- 参考：当前分支审计
- 动作：净化 descriptionHtml；修 assistantMsgId；OIDC/action capability；停止 child；补 UI/server tests
- 验收：AIChat 28/28 通过；XSS payload inert；OIDC 可 preview；commit 需显式批准；所有子进程可关闭

### P0 · Semantic Node→Python 使用 signed actor capability

- 参考：当前分支 + Tableau/Looker 边界思想
- 动作：semantic/query 与 records 拒绝 JSON 自报 actorScope；scope hash 全链一致
- 验收：unsigned/spoofed 请求 401/403；aggregate→records actor/scope/revision 一致

### P0 · 22 个模型可见工具收敛为约 7 个原语

- 参考：OpenAI 内部 Agent、Vanna API 形状
- 动作：catalog、resolve、aggregate/compare、records、trace、duplicate_search、testcase；page/recovery helpers 内聚
- 验收：生产回答覆盖不降；tool selection 错误率下降；模型可见工具 ≤8；净代码量下降

### P0 · 真实执行与最终答案 Scorecard CI

- 参考：OpenAI、Snowflake held-out VQR、Hex Evals
- 动作：60–100 个真实任务：gold SQL/result、snapshot、多轮 records、scope leakage、claim citation、latency/cost；gold 查询测试时从 context 移除
- 验收：固定 baseline；PR 阻断回归；报告 accuracy/groundedness/leakage/p95/cost；至少 3 attempts 标 nondeterminism

### P1 · typed clarification + 候选值 linking

- 参考：Looker、Snowflake、SQLBot
- 动作：高基数值受权限检索；歧义输出结构化 candidates/required fields；权限错误不重试
- 验收：错列/错值 goldens 提升；RLS 下候选不泄漏；无法消歧 fail closed

### P1 · 把关系 pathfinder 接入真正执行路径

- 参考：Wren、AWS、Fabric/Palantir
- 动作：只允许 approved edge；cardinality/explosion budget；路径 fingerprint；backend 重验；不支持路径拒绝
- 验收：任意受支持路径可执行；many-to-many explosion fail closed；current HEAD 明确包含对应 commit

### P1 · 渲染现有受验证 visualization contract

- 参考：DataHub、Hex、Google
- 动作：只从 validated result schema 生成 KPI/line/bar/table；保留 query/evidence，不先开放任意 Python
- 验收：每张图绑定 analysisRef/sourceRevision；错误/空数据不给误导图；视觉回归通过

### P1 · code-enriched context 与人工批准修复

- 参考：OpenAI、DataHub、Wren
- 动作：离线解析 pipeline/model code、lineage、description，打 context-quality；冲突建议需人工批准写回，带来源/有效期
- 验收：冲突可检测；未经批准不改语义；每条 memory/recipe 有 owner/source/expiry

### P2 · 持久 runtime 仅在有长任务需求时引入

- 参考：Palantir/商业 tracing；当前 MemorySaver 缺口
- 动作：SQLite/Postgres checkpointer、idempotency、lease、cancel/resume/replay；audit 与 checkpoint 分离
- 验收：进程重启可恢复；重复 tool call 不重复副作用；可取消；多实例测试通过

### P2 · 多源/语义 serving POC

- 参考：Wren/Cube/dbt MetricFlow
- 动作：只在明确存在多个消费端、缓存或多仓库需求时比较 compiled IR、policy、lineage、成本
- 验收：不产生双真相；Ontology 是 authoring kernel；投影可重建；真实负载证明收益

### 不建议 · 新深集成 Vanna/Dataherald/旧 MAC-SQL

- 参考：项目状态审计
- 动作：Vanna 已归档；Dataherald 停滞；MAC-SQL 老化
- 验收：不新增生产依赖；仅抽取小型可测试模式

### 不建议 · 为学术候选/可视化复制多 Agent 栈

- 参考：CHESS/CHASE/DB-GPT/Cube 多 Agent
- 动作：只把探索/候选/验证作为单主 Agent 的低置信 fallback
- 验收：默认路径保持 bounded 单 Agent；只有 A/B 明确提升才开启 fallback

## 选择建议

- **马上吸收机制，不换主架构**：OpenAI 的工具收敛/代码语义/真实执行 eval；Snowflake held-out VQR；Hex YAML Evals；Looker typed clarification；SQLBot AST allowlist；Tableau tool safety annotations。
- **可做小 POC**：Wren/Cube/dbt 只作为 Ontology 的可执行投影或 serving backend；DataHub 作为 context-quality/writeback 参考。
- **低置信 fallback**：ReFoRCE column exploration、CHESS result-shape/unit tests、XiYan DateResolver/专用模型，必须通过自有 A/B 门。
- **不建议整体集成**：Vanna、Dataherald、MAC-SQL；也不建议把 DB-GPT/Palantir 的平台复杂度搬进当前问数主链。
