Priority 0 · 关键安全/阻断

🔴 P0 — 阻断生产部署

这三项是「裸奔」级别的缺口，任何多租户或互联网暴露部署前必须解决。

P0 · 安全

API 端点全部无认证 + CORS 全开放

server/index.mjs:185-289 · backend/analytics/api.py:52
现状Node 服务（:3004）无任何鉴权；FastAPI（:3003）无中间件、无 Depends、无 HTTPBearer；CORS Access-Control-Allow-Origin: *。所有 /api/ai/chat、/api/semantic/query 完全开放。
企业级Cortex/Genie 继承仓库级 RBAC；生成 SQL 天然遵守所有访问控制；数据不离开治理边界。Vanna 2.0 内置认证、配额、审计。
风险未授权数据访问、成本被刷爆、PII 泄露。即便本体层有 actorScope，也无人验证调用方身份。
▸ 行动

① 给两套 API 加 API-Key / JWT 中间件（从 authorization 头解析 actorScope）。② CORS 收紧到已知前端 origin。③ 限流（express-rate-limit / slowapi）。④ actorScope 必须来自已认证 token，而非请求体自报。

P0 · 可观测

无 token / 成本追踪 — 无法运营、预算、计费

全仓 grep prompt_tokens|completion_tokens|cost|total_tokens = 0 命中
现状LLM 响应的 usage 元数据从不被记录。logMetric 记了延迟和工具调用数，但不记 token 与成本。无法知道单次问答花了多少、谁花得多、是否超预算。
企业级Langfuse / Arize Phoenix 按 每次调用追踪 token/cost，聚合到每用户/每 prompt 版本；MLflow Evaluation Datasets 在 CI 里追踪成本回归。
影响企业最敏感的指标之一。无成本可见性 = 无法定价、无法配额、无法发现异常消耗。
▸ 行动

① 在 companyChat.mjs 解析并持久化 usage.prompt_tokens/completion_tokens，乘以模型单价 → cost。② 注入 [vizion-metric]。③ 接 Langfuse（自托管，MIT）做成本看板。

P0 · 评测

无执行级准确率评测 + 无 CI 闸门

.github/workflows/ 不存在 · semantic-golden 仅校验语义帧不校验结果行
现状113 例 golden 仅断言语义解析（意图/指标/维度）是否对，从不校验生成的 SQL 返回的行是否正确。.github/ 只有 skills 目录，零 CI workflow。重复检索的 nDCG/MRR 模块（duplicate_search_eval.py）只被单测用合成数据调过。
企业级Genie 对比结果集（非文本匹配，接受不同排序，数值 4 位有效数字相等，至多 5000 行）；Snowflake 用列匹配 precision/recall；RAGAS faithfulness 把每个数值论断锚定到执行结果。全部跑在 CI 回归里。
风险你不知道系统准确率到底是多少。「优雅失败」的前提是能度量失败。无 CI = 任何改动都可能静默破坏准确率。
▸ 行动

① 建 NL→SQL 结果集 golden 集（20-50 例真实问题 + 期望行）。② 加 GitHub Actions 跑 npm test + pytest + 结果集对比。③ 接入 LLM-as-judge（faithfulness/relevancy）。④ 把 build_eval_cases_from_feedback 真正接入：👍/👎 → eval 用例 → CI 回归。

Priority 1 · 高优先级

🟠 P1 — 差异化能力短板

这些不阻断单机运行，但决定你能否称为「企业级」而非「优秀原型」。

P1 · 语义层

73% 的声明指标不可执行 — 语义层「有规范无引擎」

semantic_query.py:23-25,749-750 · 仅 8/30 指标在 DEFECT/TEST_RUN/TESTCASE_METRICS 白名单
现状defect.resolve_rate、kpi.defect_detection_ratio、kpi.regression_coverage、testing.pass_rate 等 22 个派生/比率/KPI 指标有完整 numerator/denominator/measure 声明，但无求值引擎——查询直接抛 SEMANTIC_METRIC_SET_NOT_EXECUTABLE。也没有时间序列分桶（无 DATE_TRUNC/strftime 聚合），trend 意图能解析但不能按时段分组。
企业级dbt Semantic Layer / Cube 把派生指标、时间分桶（day/week/month/quarter）、多粒度连接真正计算出来。这正是「metrics layer」值钱的地方——也是 Cortex 90%+ 的根基（生成针对受治理定义，而非裸 schema）。
影响用户问「DDP 是多少」「按周看缺陷趋势」会直接失败。语义层展示了它答不了的问题。
▸ 行动

① 实现派生指标求值器：解析 numerator/denominator → 两次基指标查询 → 比值。② 加 time_bucket 维度：在 executor 里按 day/week/month strftime GROUP BY。③ 先把这 8→15 个高频 KPI 做实，覆盖率即显著提升。

P1 · 可观测

无分布式追踪后端 — 多步 agent 流程不可调试

package.json / requirements.txt 无 OpenTelemetry / Langfuse / Phoenix / Sentry / dd-trace
现状有结构化日志（[vizion-metric] JSONL）和本地审计文件（logs/agent-runtime/*.jsonl），但全是扁平 stdout + 本地文件。无 span/trace 嵌套、无错误分类法、无回放机制（无法把记录的 run 重新灌进图重跑调试）。
企业级OpenTelemetry GenAI 已成标准（gen_ai.* span）；Langfuse/Phoenix 把「意图路由→规划→工具循环→流式回答」展开成可钻取的时间线 + 嵌套 span。
▸ 行动

① 接 @arizeai/openinference-vercel-ai 或 Langfuse SDK，在 LangGraph 每个节点起 span。② 建错误分类法（intent_misroute / tool_blocked / empty_result / model_error / timeout）。③ 利用已有 run-events.jsonl 实现回放命令：读日志 → 重注入消息 → 复现。

P1 · 健壮

对话记忆易失 — MemorySaver 不持久，重启即丢

langGraphChatRuntime.mjs:1,222,405 · 仅 MemorySaver，无 SqliteSaver/PostgresSaver
现状LangGraph 用 MemorySaver（进程内存），thread checkpoint 虽写到磁盘 JSON，但无代码在重启时从它 rehydrate。进程重启 → 所有会话历史丢失。
企业级多轮记忆持久化是表配项（Vanna/Cortex/Genie 全支持）；会话可跨实例、跨重启恢复。
▸ 行动

① 换 SqliteSaver（LangGraph 原生）替换 MemorySaver，或复用已写的 thread checkpoint JSON 实现 rehydrate。② LLM 上游加重试/backoff（当前 grep 无 retry）。

Priority 2 · 中优先级

🟡 P2 — 成熟度提升

提升规模化、性能与数据安全的进阶项。

P2 · 治理

行级安全 + 成本上限缺失

langGraphChatRuntime.mjs:77 · rowPolicyIds 已声明但无求值代码 · 无 token 成本上限
现状本体层 RBAC/scope/敏感字段脱敏已很强（这是 STRONG 项）。但 rowPolicyIds 是死字段——无代码把它翻译成 SQL 谓词；query.max_limit=200 只限行数，无 token/成本/执行时长上限。
企业级Snowflake Horizon 行访问策略、动态列掩码在查询时求值；Genie 截断对比在 5000 行。
▸ 行动

① 实现 rowPolicyIds → SQL WHERE 注入（你已有 scopePolicy 基建，扩展即可）。② 加 per-actor token 预算上限 + 查询超时。

P2 · 性能

无共享缓存层 + 无 SQLite 连接池 + 无语义缓存

全仓无 redis/ioredis/memcache · analytics 每次 read 新建 sqlite3.connect
现状缓存都在进程内（Node Map / 本地 SQLite/pickle）。aiContext 5 分钟 TTL、嵌入增量缓存、字段目录 memo 都是单实例，多副本不共享。无语义缓存（按查询文本 key，无法命中改写问句）。
企业级GPTCache / pgvector 语义缓存；Redis 跨实例；Cube 的 pre-aggregations 物化指标。
▸ 行动

① 加语义缓存：问题 embedding 相似度 + TTL 命中改写问句。② SQLite 开 WAL + 简单连接池。③ 高频 KPI 物化到 hot 库（复用已有 dashboard_snapshot 机制）。

P2 · 评测

无 LLM-as-judge + 反馈未回流评测

grep llm_as_judge/judge = 0 · build_eval_cases_from_feedback 仅测试调用
现状👍/👎 反馈已采集（feedback_store.py），build_eval_cases_from_feedback 也写了，但从未接成闭环——反馈没变成回归用例。无 LLM-as-judge 自动评分。
▸ 行动

① 定时把确认反馈导出为 eval 用例（README 已有命令）。② 加 faithfulness/answer-relevancy LLM-judge。③ 形成「生产流量 → 标注 → eval 集 → CI 回归 → 改进」闭环。

Priority 3 · 战略机会

🔵 P3 — 拉开身位的创新

基于你已有架构可低成本切入的前沿方向。

P3 · 前沿

多路径生成 + 自我纠错（CHASE-SQL / MARS-SQL）

你的 agent/ 历史（仅 .pyc）曾有 multi_executor 3 路径 + QueryFixer，但当前 Node 运行时未启用
机会CHASE-SQL（3 路径生成 + 偏好优化选择，BIRD 73%）和 MARS-SQL（可训练多智能体自纠）是 2025-26 SOTA。你的 Python agent 曾经实现过多路执行 + 结果签名一致性比较 + LLM 仲裁 + 自纠重试（β=3），但这些能力没迁移到当前 Node 运行时。
▸ 行动

把历史 Python 的多路径/自纠能力，以「生成多候选 → 执行结果对比 → 选优」的形式移植到语义查询执行器，作为派生指标引擎（P1）的姊妹项。

P3 · 前沿

知识图谱接地 — 把 schema 准确率从 16% → 54%

Sequeda et al. 2023: GPT-4 零样本 16.7% → KG 接地 54.2%
机会你已有 27 条关系 + 实体/维度/指标的图结构本体。RAGAS 研究表明把它作为 KG 检索接地（而非纯文本 prompt），可大幅提升 schema linking 准确率。你的 /api/ontology/fields/search 字段目录已是雏形。
▸ 行动

把本体关系图建成向量索引，规划阶段检索相关子图注入 prompt，而非塞全量 schema。

P3 · 体验

安全失败 + 多步计划断点续跑

机会企业级共识：「在 90% 准确率优雅失败」比「90% 硬答但可能幻觉」更安全。你已有空结果自愈诊断（diagnose_analytics_empty），但多步计划中途失败仍是单错误抛出，无断点续跑。
▸ 行动

① 多步 plan 加 checkpoint，失败可从断点续。② 明确「不确定时拒绝并解释」路径，降低幻觉。

Strengths · 已有优势（别拆掉）

🟢 你做对了什么

这些是大多数原型没有的、真正企业级的能力——改进时务必保留。

🛡️ 三层只读强制 + 写动作治理

SQLite ?mode=ro + PRAGMA query_only + 本体操作白名单。写动作（删/改/评论）编译期强制 blocked 或 dry-run+人工批准+三重审计。这是真正的企业级护栏。

🔒 PII / 敏感字段 SHA-256 脱敏

confidential/restricted 维度按 actor 脱敏；scopePolicy 强制 SEMANTIC_SENSITIVE_FIELD_DENIED。VIN 等保密字段处理到位。

📐 指纹 + 版本钉定的证据链

每个回答携带 ontologyVersion/schemaFingerprint/sourceRevision/quality，声明-证据绑定约束（coverage=1）。这是 Cortex/Genie 级的 claim-evidence binding。

🧠 混合检索 + RRF + 反馈重排

BGE 稠密 + TF-IDF 稀疏 → 倒数排名融合 + 提示加权 + ClickBoostReRanker（NDCG 回归守护才部署）。带 nDCG/MRR 评测模块。重复检索这块比多数商业产品还完整。

🏗️ 工具/流式严格分离 + 策略门

工具只在规划节点跑，流式回答无工具权限且主动剥离 DSML 伪工具标记。意图白名单限定 LLM 可选工具——防止越权工具调用。

📚 CI 守护的本体编译管线

9 源文档 → Ajv schema 校验 → 跨文档引用完整性 → 指纹 → --check 防 stale。声明层治理成熟度极高。
