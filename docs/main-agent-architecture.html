主 Agent 模型架构

这套模型不是一个孤立的 LLM，而是由 React Chat UI、Node SSE 网关、LangGraph 状态机、typed tool planning、治理后的 analytics/ontology API、duplicate-search bridge 和公司模型端点共同组成的本地智能分析系统。

Business Flow

业务处理流程图

用户的问题先被收敛成可治理的业务意图，再按意图选择工具、补充证据、回到最终模型生成回答。重复搜索、缺陷统计、测试覆盖率和本体能力不会混在一起猜。

Sequence Diagram

一次完整问答的时序图

时序上有两次模型交互：第一次是工具规划，第二次是最终自然语言回答。工具结果以 SSE 的 tool-input/tool-output 事件先给 UI，再进入最终上下文。

Tool And Data Boundaries

工具、数据与治理边界

Agent 能做的事情来自 intent profile 和 tool policy，不是模型随口决定。每个工具都有 JSON schema、允许意图和后端 allowlist。

意图层
metric_query、coverage_query、record_query、traceability、schema_discovery、duplicate_search、business_risk_assessment 等 profile 决定候选工具集。
规划层
模型只在 selected toolset 内生成 OpenAI-style function calls。每轮最多截取 3 个 planned calls，循环步数默认 4。
执行层
policy gate 校验工具是否允许；空 analytics 结果会自动追加 diagnose_analytics_empty，而不是直接回答“没有数据”。
query_analytics diagnose_analytics_empty query_analytics_fallback query_semantic_metrics query_semantic_records query_traceability query_testing_coverage_project_status query_testing_coverage_aida_status search_duplicates ask_clarification
