### 3. 纠正上次报告几个对标错误(基于用户 competitive-positioning 核查)

- **Cortex Analyst 被低估**:它的 Semantic View 不是静态 YAML,是 schema 级对象(逻辑表/facts/metrics/dimensions/relationships/custom instructions/access modifiers/verified queries),集成原生 RBAC,生成 SQL 受既有访问控制约束,支持多轮上下文,有 Cortex Analyst Evaluations(verified Q/SQL 对比执行结果 + accuracy/regression/latency)。上次只标"商业 warn",实际是**直接对标的第一梯队**。
- **Databricks 上次漏了**:应是 **Genie / Genie Agents / AI-BI on Unity Catalog**(不是泛泛的"AI Functions")。Genie 有语义 curation、verified answers、visual output、knowledge updates、平台级治理(UC row filters/column masks/dynamic views/ABAC)。
- **LangGraph / CAMEL-AI 不该和数据 agent 产品同象限**:它们是框架/参考架构。LangGraph 是底层有状态编排框架(其 SQL tutorial 明确警告"最小 SQL 工具非生产安全");CAMEL-AI 是多 agent 研究/开发框架。应放"构建参考"组。
- **Vanna 描述过时**:Vanna 2.0 有 user-aware permissions/RLS/streaming tables/conversation storage/tool memory/web 组件,但 repo 已 archived(2026-03-29)。作架构参考,不作活跃对标。
- **Palantir "本体即企业操作系统" 仍是终局参照**,但用户文档明确:Data-Agent 当前不应放"NL2SQL accuracy × insight depth"图右上,直到 accuracy/safety/insight 在稳定评测集上被度量。

### 3.1 WrenAI:从 "NL2SQL 引擎" 升级为 "agent-native GenBI engine"

实抓 `https://raw.githubusercontent.com/Canner/WrenAI/main/README.md`(2026-08-10)的核心变化:

- **新定位三拍**:**Generate**(治理 text-to-SQL + charts,靠 schema-aware retrieval + MDL planning + dry-plan validation + structured errors)、**Deploy**(浏览器侧 dashboard via `wren-core-wasm`,一条命令部署到自己的 Vercel/Cloudflare Pages)、**Know**(MDL + `instructions.md` + `queries.yml` + LanceDB 本地 memory hybrid retrieval)。22+ 数据源。
- **agent-native 分发**:`pip install wrenai` + `npx skills add Canner/WrenAI`(给 Claude Code/Cursor/Cline/Codex 自动装 ~50 行 discovery stub)+ `wren skills get onboarding/enrich-context/genbi` + `wren ask "<q>" --guided|--direct` + `wren query --sql '...'`。
- **open core 边界(对你的关键启示)**:OSS(Apache 2.0)= MDL 语义层 + 治理 text-to-SQL + MCP server + CLI + 22+ 连接器;**商业(Cloud / Enterprise Plus)= RLS/CLS、用户组访问控制、GenBI UI/dashboard、GenBI Apps、Agentic Mode、context preparation、高级安全审计、SLA**。
- **对 Data-Agent 的意义**:① WrenAI 混合集成仍然可行；Data-Agent 已有证据、身份和受治理计划基础，但 `graphPathfinder` 尚未具备 wren-core 类的可执行 join 契约，不能因 BFS 可达性判定已覆盖其核心能力。② MDL 的 Git-friendly schema 规范仍值得借鉴。③ `instructions.md` + memory 的 context layer 对应尚未完成的 ontology learning loop。

### 3.2 学术:执行准确率天花板 vs 真实场景地板(差距巨大)

实抓 `Awesome-LLM-based-Text2SQL`(DEEP-PolyU,TKDE 2025 综述配套 repo,2026 持续更新)的榜单:

| Benchmark | 场景 | 当前 SOTA | 对 Data-Agent 的意义 |
|---|---|---|---|
| BIRD(Test EX) | 跨域知识增强 | **81.95%**(AskData+GPT-4o, 2025-12) | 不直接适用(你不生成任意 SQL) |
| Spider 1.0(Test EX) | 经典跨域 | 91.2%(MiniSeek 闭源);DIN-SQL 85.3% | 同上 |
| **Spider 2.0**(Lite) | **真实企业工作流** | **44.5%**(AgenticData+Qwen3) | **这才是你的对标尺** |
| **BIRD-CRITIC**(SR) | **修真实 SQL bug** | **43.33%**(ByteBrain-Agent) | 你的 bounded recovery 可对标 |

**结论**:学术 SOTA 在"干净 benchmark"上已 80%+,但**真实企业场景(Spider2.0/BIRD-CRITIC/BIRD-INTERACT)最高才 44% / 43% / 21%**。这组数字是你 competitive-positioning 文档"BIRD/Spider 只作 secondary screening、真实 task scorecard 才是 KPI"的硬证据。**你的护城河不在拼 BIRD 81.95%,而在 DTSV 真实 task 的 scorecard**(你 doc P0.1 的 60-100 真实任务)。

### 3.3 商业平台 2026 的共同趋势

三个信号一致:**语义层 schema 化 + 平台级治理 + verified-query 评测**。

- **Snowflake Cortex Analyst**:Semantic View 已是 schema 级对象(逻辑表/facts/metrics/dimensions/relationships/custom instructions/access modifiers/verified queries),集成原生 RBAC,生成 SQL 受既有访问控制约束,有 Cortex Analyst Evaluations(verified Q/SQL 对比执行结果 + accuracy/regression/latency,但限制:每次一个 semantic view、无多轮评测、人工 curate)。
- **Databricks Genie / Unity Catalog**:2026 新增分析 UC volumes 文件(PDF/图片/slides)、Genie Code 嵌入式 NL→SQL、any-agent 跨 Genie 互操作。UC 提供 row filters / column masks / dynamic views / ABAC,**在数据平台层强制**。Genie 可从 author feedback 学知识库更新。
- **共同点**:它们都把"语义定义 + 治理 + 评测"沉到平台层,而非靠 prompt。这正是你的 `analysisPlanner` + `agentAuth` + golden fixture 走的路——**方向和巨头一致,差距在工程化闭环(你的 per-user 部署边界 / scorecard / CI 未闭环)**。

### 3.4 Vanna archived 的信号

Vanna 2.0(2026-03-29 archived)尽管有 user-aware permissions/RLS/streaming tables/conversation storage/tool memory/web 组件,仍停止维护。**信号**:纯"中文 NL→SQL"单点产品长期会被通用 agent(Claude Code/Cursor/Codex)+ 平台(Cortex/Genie)吞并。**你的护城河必须锚定垂直 DTSV ontology 深度 + 治理 + 证据纪律**,而不是和通用 agent 拼 SQL 准确率——这条结论 08-03 报告给出,08-10 有了更多证据(WrenAI 转 agent-native、Vanna archived、学术真实场景地板)。

## 四、项目代码级总结(按三组分类)

采用你 competitive-positioning 文档的**三组分类法**(比 08-03 的"四梯队"更准确):A 直接企业数据 agent(决定产品竞争力)、B 语义/治理基础设施(决定企业护城河)、C NL2SQL/构建参考(决定实现机制)。每组只列与 Data-Agent 有对标价值的项,🟢=实抓 README/官方文档(08-10 复核)、🟡=训练知识 + 论文/arxiv、🔴=闭源官网原理。

### A 组 · 直接企业数据 agent(产品竞争力对标)

这一组决定"用户为什么会用你而不是 Cortex/Genie"。你的差异化:**垂直 DTSV ontology 深度 + 中文原生 + 证据纪律**(它们是通用平台,你是垂直专家)。

#### A1. Snowflake Cortex Analyst + Semantic Views 🔴🟢(08-10 复核官方)

- **定位**:Snowflake 原生的 NL→结构化数据产品,REST API + 自动模型选择。
- **关键架构**:Semantic View = schema 级对象(logical tables / facts / metrics / dimensions / relationships / custom instructions / access modifiers / verified queries);legacy YAML 仍支持但新构建指向 Semantic Views。生成 SQL 受 Snowflake RBAC 约束。Cortex Analyst Evaluations 用 verified Q/SQL 对,对比**执行结果**(不是文本),报 accuracy/regression/latency,有编程化工作流。
- **限制**:每次 run 一个 semantic view、无多轮评测、评测集人工 curate;不能访问前序 SQL 结果集;宽泛非 SQL 业务洞察受限。
- **链接**:[Cortex Analyst](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst) · [Semantic Views](https://docs.snowflake.com/en/user-guide/views-semantic/overview) · [Evaluations](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst-evaluations)
- **对 Data-Agent**:你的 `analysisPlanner` visualization profile(kpi/line/bar/grouped_bar/table)和它的 metrics/dimensions/custom instructions 是同构的——**你的可视化渲染(P0.2)可直接借鉴 Semantic View 的"verified query + 执行结果对比"评测思路**。

#### A2. Databricks Genie / Unity Catalog 🔴🟢(08-10 复核,上次漏了)

- **定位**:AI-BI 内的 NL 接口,返回 SQL + 结果表 + 可视化;Genie Spaces 已改名 Genie Agents。
- **关键架构**:两层语义上下文——UC metadata(表/列/注释/关系)+ 额外语义定义(joins/fields/measures/filters/synonyms/instructions/example SQL/UC functions)。parameterized example queries 和 functions 可成为 **trusted assets** 产出 verified answers。UC 的 row filters / column masks / dynamic views / ABAC policies **在数据平台层强制**(不是应用层)。Genie 从 author feedback 学知识库更新推荐。
- **2026 新增**:分析 UC volumes 文件(PDF/slides/images)、Genie Code 嵌入式 NL→SQL、any-agent 跨 Genie Agents 互操作。
- **链接**:[Genie Agents](https://docs.databricks.com/aws/en/genie-agents/) · [质量调优](https://docs.databricks.com/aws/en/genie-agents/tune-quality) · [UC row filters/masks](https://docs.databricks.com/aws/en/data-governance/unity-catalog/filters-and-masks/)
- **对 Data-Agent**:① UC 的"治理在平台层强制"vs 你的"治理在应用层(agentAuth + actorScope)"——**长期你想把 RLS 下沉到数据层**(你 doc 维度4 的深度版本),但短期应用层足够。② Genie 的"trusted assets = verified answers"思路 = 你的 business_rules + golden fixture,可借鉴其"parameterized query 成为可信资产"的产品化。

#### A3. ThoughtSpot Spotter 🔴

- **定位**:搜索驱动的 NL→analytics,Spotter 是其 AI 副驾驶。
- **架构要点**:SearchQL 把 NL 转 Fact-based 查询(类似你的结构化契约,不生成任意 SQL);答题级置信度 + "我无法回答"兜底;可视化对话式追问。
- **链接**:[ThoughtSpot](https://www.thoughtspot.com/product/ai)
- **对 Data-Agent**:**"答题级置信度 + 主动承认不确定"** 正是你 doc 维度7 P1"真实置信度"要对标的——你已有 `answerValidator` 的因果护栏,缺置信度分数计算。

- **结论**:从"P0 试水决策门"降级为"P2 仅在多源联邦需求出现时再评估"。把 P0 精力放 scorecard + 授权边界 + 可视化。
