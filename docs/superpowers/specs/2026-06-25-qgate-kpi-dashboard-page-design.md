# QGate KPI Dashboard Page Design

## Goal

Add a left-sidebar Vizion Lab dashboard page named `QGate KPI Report` that displays the existing native `QGate KPI Dashboard` HTML report without changing the report's visual content, charts, filters, or drilldown behavior.

## Scope

This first migration integrates only the `QGate KPI Dashboard` standalone HTML report generated by Vizion Lab's native QGate report generator.

Out of scope for this migration:

- `2024 vs 2025 KPI Analysis`
- a report switcher between dashboard and compare reports
- a full React/Recharts rewrite of the QGate report
- changes to AI Chat or Duplicate Search behavior

## Current Behavior

Vizion Lab can generate QGate KPI reports as standalone static HTML files under `docs/qgate-reports/generated_runs/<timestamp>/`. The dashboard report is produced by `backend/analytics/qgate_kpi_dashboard_report.py` and includes its own CSS, JavaScript, payload, filters, charts, and tables.

The existing Vizion Lab frontend uses a left `DashboardSidebar` plus `Index.tsx` switch-based page registration. `AIChat.tsx` has its own internal interaction tabs, but those tabs control chat modes rather than dashboard navigation.

## Desired Behavior

The left dashboard sidebar includes a new navigation item:

- label: `QGate KPI Report`
- page title: `QGate KPI Report`
- page subtitle: `QGate KPI Dashboard 迁移视图`

When the user opens the page:

1. The outer shell keeps Vizion Lab's existing sidebar, sticky header, background, spacing, and card styling.
2. The page finds the latest generated `qgate_kpi_dashboard_<timestamp>.html` file.
3. The page displays that HTML report inside an isolated `iframe`.
4. If no dashboard report exists, the page shows an empty state telling the user to generate the report first.
5. If loading fails, the page shows an error state and a retry action.

## Architecture

Use an iframe-based first phase. This is intentionally conservative because the current generated report is a complete standalone HTML document with global CSS selectors, `body` styles, `:root` variables, DOM ids, and inline JavaScript. Injecting it into the React DOM would risk style collisions with Vizion Lab, while a full React rewrite would require rebuilding report logic and interactive behavior.

The migration has three boundaries:

1. **Report generator boundary**: keep `backend/analytics/qgate_kpi_dashboard_report.py` responsible for report content.
2. **Node API boundary**: expose a small safe report discovery and file-serving surface from `server/index.mjs` or a focused helper module.
3. **Frontend page boundary**: add a focused React page that renders Vizion Lab chrome and an iframe pointing at the served report HTML.

## Backend API Design

Add a small report helper that scans only `docs/qgate-reports/generated_runs/` for dashboard files matching:

```text
qgate_kpi_dashboard_*.html
```

The helper returns the newest dashboard report by run directory timestamp or file modification time.

Expose these endpoints through the existing local Node server on port 3004 and Vite proxy:

```text
GET /api/qgate-reports/latest-dashboard
GET /api/qgate-reports/dashboard-html?run=<run>&file=<file>
```

`latest-dashboard` response when a report exists:

```json
{
  "available": true,
  "run": "20260611_152821",
  "fileName": "qgate_kpi_dashboard_20260611_152821.html",
  "generatedAt": "2026-06-11T15:28:21.000Z",
  "iframeUrl": "/api/qgate-reports/dashboard-html?run=20260611_152821&file=qgate_kpi_dashboard_20260611_152821.html"
}
```

`latest-dashboard` response when no report exists:

```json
{
  "available": false,
  "message": "No QGate KPI Dashboard report has been generated yet."
}
```

The HTML-serving endpoint must reject path traversal and must only serve files inside `docs/qgate-reports/generated_runs/<run>/` whose file name matches `qgate_kpi_dashboard_*.html`.

## Frontend Design

Create `src/components/dashboard/pages/QGateKpiReport.tsx`.

The page should:

- load `/api/qgate-reports/latest-dashboard` on mount
- show a compact toolbar with the report name and generated run metadata
- render an iframe with `src={iframeUrl}` when available
- use a stable container height so the page does not jump while loading
- display an empty state when no report is available
- display an error state with a retry button on fetch or iframe load errors

The iframe must not be styled internally by Vizion Lab CSS. The outer container can use existing `dashboard-card`, `bg-card`, `border-border`, and `text-muted-foreground` conventions.

Register the page in:

- `src/components/dashboard/DashboardSidebar.tsx`
- `src/pages/Index.tsx`

## Testing Strategy

Add focused tests for the safest boundaries:

1. Server helper finds the newest `qgate_kpi_dashboard_*.html` report.
2. Server helper ignores the compare report and unrelated HTML files.
3. Server helper rejects path traversal and non-dashboard file names.
4. Frontend page shows an empty state when `available=false`.
5. Frontend page renders an iframe with the returned `iframeUrl` when `available=true`.
6. Sidebar registration exposes `QGate KPI Report`.

Run focused tests first, then a broader frontend build if package metadata is valid.

## Known Precondition

The current working tree appears to have an invalid `package.json` structure in the scripts area. If implementation needs `npm run build` or `npm test`, repair that syntax as part of the migration because it blocks normal Node tooling. Keep that repair minimal and do not change unrelated dependency versions.

## Rollout

This change is additive. Existing pages, AI Chat, Duplicate Search, and QGate report generation remain unchanged. If the iframe page has a problem, removing the new sidebar item and page registration disables the integration without affecting report generation.
